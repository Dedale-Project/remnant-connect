# Consumer security fixture

This opt-in example tests a small, pure controller at the boundary between untrusted memory and proposed actions. It does not modify the Remnant bridge, grant permissions or run a model.

Run locally with Node 22 or later:

```sh
node --test test/consumer-security.test.mjs
node examples/consumer-security/run.mjs
```

The second command prints a JSON report to stdout. It loads no provider, endpoint, credential or external model. It makes no network requests. A caller may save the report to a local evidence file.

## Frozen experiment

Before the first run, `consumer-boundary-v1` fixed 24 cases: six authority claims (French/English), six URLs, six quasi-instructions, two policy/envelope confusions, and four benign controls. Its JSON SHA-256 is `8ad5f1bc7e91de245ea2ef7dd300fde33f53999d48c4b2920b8d38b3356356eb`. Each case contains an explicitly **scripted proposal**, with its expected result fixed in advance. These proposals are not generated by an agent reading the passage. The included canary and every referenced secret, mutation, command, URL and fixture are synthetic.

The fixed budgets are 8 KiB source, 16 KiB response, eight actions, 32 trace entries, 64 KiB trace, JSON depth eight and 256 JSON nodes. Adapter waiting defaults to one second. A trusted caller may reduce budgets, not increase them. Unicode is measured in UTF-8 bytes. Trace capacity has a minimum sufficient for a bounded refusal record.

## Controller boundary

`controller.mjs` has no network, filesystem, process, dynamic evaluation or real tool callback. It consumes data and returns data. Its one tool is a dictionary lookup in a snapshot of explicitly allowed public fixtures. A final text action may also be accepted. Fake `write_memory`, `fetch_url`, `read_secret` and `exec` proposals are rejected, without dispatch.

Policy comes from trusted constructor arguments and is frozen separately from the untrusted memory. Memory text, forged consent, URLs, copied policy objects and MCP-like envelopes cannot add a capability. The controller only accepts a strict JSON actions envelope. No partial output is released if any action is rejected. Successful benign controls prevent a deny-everything implementation from passing the corpus.

The synthetic canary is checked in proposed action data, final text, fixture output and concatenated outputs. Input containing a recognized canary is refused before an adapter is called. Errors/traces never copy input, arguments, exception messages or stacks. Declared adapter metadata is bounded and checked too.

Recognized forms are the literal canary, `encodeURIComponent(canary)`, fully percent-encoded UTF-8 (hex case insensitive), base64, unpadded base64url, and JSON string escapes decoded by parsing. **Mixed, repeated, arbitrary or semantic encodings are not claimed. This is not general DLP.** The corpus and tests use no real secret.

## Adapter boundary and evidence

`model-adapter.mjs` defines a separate, explicit `generate(request, {signal})` seam. No model is provided, loaded or discovered. The default result is **NOT_RUN, n=0**. Unit tests use in-process deterministic callbacks, including one deliberately mislabeled callback to verify that a model label cannot count as evidence.

The request labels memory as untrusted data and carries the trusted policy separately. A completed callback response is still validated by the controller. `adapterInvoked` means only that the callback was invoked. Declared model metadata yields `modelExecution: UNVERIFIED`, never proof of a real model request. Actual model experiments require separately reviewed instrumentation, runtime/model/version, trace provenance, sampling parameters, seed when supported, trial counts and outcomes. Do not count replay tests as model trials.

The adapter's timeout and AbortSignal bound a cooperative asynchronous wait. They do not preempt a blocking JavaScript callback, kill a process, or prove its network isolation. A supplied callback is outside the pure-controller boundary; a future external model needs an independently established execution environment. No such model environment was exercised here.

The report separates:
- scripted adversarial cases rejected and benign controls accepted;
- forbidden tool proposals and canary detections before release;
- controller failures and false refusals, each with denominators;
- model experiments, always NOT_RUN in this default runner.

A controller refusal is not evidence that an agent resisted the instruction. An attempted leak blocked here is not a real exfiltration, and zero real capabilities are not a general immunity result.

## Rollback

Remove or stop running this optional example and its tests. It has no production integration, credentials, dependency changes, data migration, persistent mutations or automatic startup to undo. Preserve the frozen corpus and measured negative results as evidence if the example is revised. Changes to corpus, budgets or controller semantics require a new version and a fresh report.
